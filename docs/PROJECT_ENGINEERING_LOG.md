# 基于示教学习的多触手智能柔性末端执行器工程开发日志

本文档用于记录本项目从 CubeMX 初始化、STM32G474 三电机 FOC 硬件联调，到 STM32H743 多触手控制、VL53L8CH 感知、示教数据采集、端侧模型训练部署和整机验证过程中遇到的主要问题、解决方式及仍需继续处理的事项。

记录原则：

- 优先记录工程事实，不写空泛总结。
- 每个问题尽量包含：现象、原因判断、处理方法、当前状态。
- 后续可以根据 Git commit 和工程快照补充具体日期。
- 本文档偏工程记录，不是正式论文或汇报稿。

## 1. 项目基本信息

### 1.1 项目目标

使用 STM32G474VET6 控制 3 个 BM352006 无刷电机，用于带减速器和线轮的拉索式机构。

当前软件目标是：

- 先完成单电机 FOC 链路。
- 再验证电流环、速度环、位置环。
- 最后扩展到三电机统一管理和调度。

### 1.2 当前硬件分工

| 功能 | 外设 | 说明 |
|---|---|---|
| 电机 1 PWM | TIM1 | 三相互补 PWM |
| 电机 2 PWM | TIM8 | 三相互补 PWM |
| 电机 3 PWM | TIM20 | 三相互补 PWM，当前主要调试对象 |
| 电流采样 | ADC1 / ADC3 / ADC4 | 每个 ADC 采一个电机三相电流 |
| 温度/辅助采样 | ADC2 | 低频模拟量采样 |
| DRV 配置 | SPI1 | 配置 DRV8323S/DRV8328 |
| 编码器读取 | SPI3 | 读取 SPI 磁编码器 |
| 调试串口 | USART1 | VOFA JustFloat |
| 主控通信 | FDCAN1 | 后续与上位主控通信 |

### 1.3 当前重点调试链路

当前主要以一台电机为对象进行联调：

```text
TIM20 PWM
-> DRV3
-> 电机
-> ADC1 三相电流采样
-> SPI3 编码器 CSN3
-> motor_core 电流环/FOC
-> VOFA 观察
```

## 2. 软件模块结构

| 模块 | 主要作用 |
|---|---|
| `Config.h` | 全局参数、限幅、默认 PID、采样配置 |
| `Motor_type.h` | 电机对象、控制状态、采样数据结构 |
| `control_pid.c/h` | 通用 PID 基础算法 |
| `foc_drive.c/h` | Clarke/Park/SVPWM/CCR 写入 |
| `motor_core.c/h` | 单电机控制主链路、校准、闭环接口 |
| `adc_app.c/h` | ADC DMA 启动、稳定帧缓存、诊断 |
| `spi_encoder.c/h` | SPI 编码器 DMA 读取、角度、多圈、速度 |
| `drv_drive.c/h` | DRV8323S 寄存器读写、默认配置、CAL 控制 |
| `Vofa_debug.c/h` | VOFA JustFloat 调试主题 |
| `timer_app.c/h` | 定时任务、TIM4/TIM6/TIM7/TIM3 等辅助节拍 |

目前文件划分的基本原则：

```text
Config.h       只放参数
Motor_type.h   只放数据结构
control_pid    只做通用 PID
foc_drive      只做 FOC 数学和 PWM 写入
motor_core     组织单电机控制数据流
```

### 3.1 VOFA 调试链路

完成内容：

- 使用 USART1 输出 VOFA JustFloat 数据。
- 支持多调试主题切换。
- 使用 DMA 发送，避免阻塞主循环。

- 给每个主题固定通道含义。
- 根据调试目标调整 VOFA 周期。

当前状态：

- VOFA 可正常使用。
- KEY3 可切换调试主题。
- 后续仍需要控制通道数量，避免高频调试影响实时性。

### 3.3 ADC 采样链路

完成内容：

- 建立 `adc_app` 模块。
- ADC1/ADC3/ADC4 分别采三相电流。
- 使用 DMA 和软件稳定帧缓存。
- 增加 ADC 诊断主题。
- 增加 STM32 ADC 自校准接口。

遇到的问题：

- ADC raw 不更新或固定。
- DMA 完成计数很慢或异常。
- Continuous mode 和外部触发逻辑混乱。
- VOFA 读取与控制链路消费数据互相影响。
- TIM20 触发 ADC 的位置会影响采样真实性。
- 低侧采样窗口不足时，某些相电流会失真。

解决方式：

- 关闭不合适的连续转换模式。
- 使用 TIM 触发 ADC。
- DMA 完成后只更新稳定帧和标志。
- 控制链路逐步转到 ADC 完成后执行。
- 尝试使用 TIM20 CC3 / TRGO2 作为采样触发点。
- 引入 duty 限幅和三相电流重构思路。

当前状态：

- ADC 链路能够运行。
- 电流环可以基于 ADC 数据闭环。
- 低侧采样窗口和负载下采样畸变仍是重要风险。

待继续处理：

- 验证不同 duty 下 raw 是否贴近 2048 或削顶。
- 验证 `ia + ib + ic` 是否接近 0。
- 验证堵转/负载下三相采样是否真实。
- 后续可能需要更完善的低侧采样重构策略。

### 3.7 FOC 电角度 offset 校准

完成内容：

- 实现单点 d 轴吸附校准。
- 校准时输出 `vd > 0, vq = 0, theta_cmd = 0`。
- 转子吸附后读取编码器机械角。
- 计算 `foc_elec_offset`。

校准核心逻辑：

```text
控制器人为定义 theta_cmd = 0 为 d 轴方向
给定 vd > 0 后，转子磁链被吸附到该方向
读取此时编码器机械角 theta_mech_align
计算 offset，使该位置在控制坐标中等于 0
```

遇到的问题：

- 一开始对“控制坐标 theta=0”和“编码器原始角度 0”关系理解不清。
- 两点校准流程容易受编码器错误和吸附不稳定影响。
- 校准有时会卡卡的。

解决方式：

- 暂时关闭两点校准。
- 回退到单点锁定校准。
- 保留两点校准代码，后续有需要再恢复。

当前状态：

- 单点校准可用。
- offset 精度仍可能影响负载下扭矩平滑性。

待继续处理：

- 验证校准后 `id` 是否接近 0。
- 验证给 `iq` 后是否明显混入 `id`。
- 后续可尝试双向吸附平均或更稳的两点校验。

### 3.8 电流环控制

完成内容：

- 实现 id/iq 电流环 PID。
- 电流环输出 vd/vq。
- vd/vq 经 FOC 输出到 PWM。
- 电流环已经能够让电机运行。

遇到的问题：

- iq/id 波形抖动。
- 堵转时 iq 可能飙高。
- 电机负载下有类似步进吸附的卡顿。
- 三相电流在某些状态下被削顶。
- 快环放进 ADC 回调后电机更稳，但 VOFA 和按键变卡。

解决方式：

- 将电流环放到 ADC DMA 完成后运行。
- 对快环做减负：缓存 ARR、直接写 CCR、减少通用函数调用。
- 调整 duty 限幅和采样点。
- 尝试三相电流重构。
- 排查空载 `id` 规律震荡时，曾重点怀疑电角度 offset、重构相切换和 ADC 采样点。
- 最终确认主要原因之一是电流环死区设置过大：小误差被死区吞掉，误差积累后再突然参与控制，形成规律震荡。
- 缩小电流环死区后，空载电流环稳定性明显改善，电机运行恢复平顺。

当前状态：

- 电流环可以跑。
- 空载和带负载表现均已有明显改善。
- 当前新电机电流环已基本稳定，可作为后续速度环和位置环调试基础。

待继续处理：

- 确认电流采样真实性。
- 确认 iq/id 方向和相序。
- 在当前较小死区基础上继续细调 PID 参数。
- 后续调参时必须记录死区数值，避免再次把过大死区误判为电角度或采样问题。

### 3.8.1 空载 id 规律震荡问题记录

现象：

- 新换电机后，电流环空载运行时 `id` 出现规律性震荡。
- 有负载或用手按住电机时反而更稳定。
- `CH2/CH3` 即 `i_alpha/i_beta` 在有有效电流时能呈现正弦/余弦关系。
- 一度怀疑电角度 offset、重构相切换、采样窗口和反电动势补偿。

检查过程：

- 固定重构相后，`id` 震荡减轻，但按住电机时出现尖叫和卡顿，说明固定重构相只能用于定位，不能作为正常运行方案。
- 尝试观察 `id/iq`、`i_alpha/i_beta`、三相电流、重构相编号和 ADC 触发 CCR。
- 发现有负载时电机和电流表现反而正常，说明电角度大错误的可能性下降。
- 继续检查电流环参数后确认，过大的电流环死区会让小电流区反馈迟钝，导致误差周期性积累和释放。

最终原因：

- 主要原因是电流环死区设置过大。
- 空载时真实电流较小，死区占比过大，电流环不能连续细微调节。
- 误差越过死区后控制量突然变化，表现为规律性 `id` 震荡和空载不平顺。

处理结果：

- 调小电流环死区后，电机空载稳定性明显改善。
- 当前电流环已达到比较稳定的状态。
- 后续速度环、位置环调试应基于当前较小死区配置，不要再随意放大死区。

经验记录：

- `id` 规律震荡不一定优先等同于电角度错误。
- 如果“有负载正常、空载震荡”，应优先检查低电流区死区、零漂和测量信噪比。
- 死区属于控制非线性，过大时会制造类似步进/吸附/周期震荡的现象。

### 3.10 2026-05-31 长周期联调问题汇总

本节记录本轮长对话中连续排查的问题链路。记录重点是“现象 -> 判断 -> 修改/验证 -> 结果”，用于后续断电、换电机或回退版本时快速恢复上下文。

#### 3.10.1 CAN / FDCAN 通信方案讨论

现象和需求：

- 当前电流采样问题一度阻塞速度环和电流环继续推进。
- 后续需要开始规划与 H7 主控之间的 CAN 通信。
- 讨论过标准 CAN、扩展 CAN ID、CAN FD / FDCAN 的区别，以及是否需要单独 `can_app`。

处理结论：

- 标准 CAN 更适合简单、兼容性强、数据量小的控制命令和状态反馈。
- CAN FD / FDCAN 更适合后续较大数据包、高速调试、更多状态量和扩展协议。
- 工程结构上建议后续单独建立 `can_app`，不要把通信解析散落在 `main.c` 或 motor 模块内。

当前状态：

- 当前阶段仍以单电机 FOC 联调为主，FDCAN 仅完成方案讨论，尚未作为主线实现。
- 后续进入主控通信阶段时，应先定义帧 ID、数据缩放、心跳、故障码和电机编号映射。

#### 3.10.2 MT6816 SPI 编码器读取问题

现象：

- MT6816 通过 SPI3 + DMA 读取角度时，静止大多正常，手动转动或电机转动时频繁出现 parity / no magnet / frame 错误。
- 曾怀疑 SPI 速度、软件分频、CS 时序、DMA 回调被打断、不完整帧等问题。
- 一度出现角度通道从小值直接跳到大值，导致电机震动。

检查和修改：

- 对照 MT6816 手册重新确认 8-bit SPI 读取方式。
- 尝试过 3 字节连续读取、4 字节读取、分两次读取高低寄存器等方式。
- 优化 CS 释放位置，确认 DMA 完成回调后才释放 CS。
- 尝试 SPI 分频、TIM7 读取频率、软件二分频和单回调读取。
- 增加 VOFA 原始接收缓存观测，定位原始字节跳变。

结果：

- 最终确认其中一部分异常来自编码器芯片本身，换芯片后角度读取明显恢复正常。
- 编码器读取链路目前可支持后续闭环调试。
- 经验上，编码器问题不能只看校验错误率，也要直接观察原始 RX 字节和 angle jump。

#### 3.10.3 编码器测速与速度环输入

现象：

- 速度环接入后，实际速度曲线震荡尖锐，P 项很小仍然会出现规律波动。
- 简单单次差分、滑动窗口、固定 dt、DWT 时间差等方案都讨论过。
- 曾出现堵转后松开产生速度尖峰，速度环输出 `iq_ref` 呈波浪状。

检查和修改：

- 讨论过编码器 4 kHz 更新、TIM7 1 kHz 速度环之间的关系。
- 尝试从“每次 TIM7 用上一次角度差分”简化，再恢复滑动窗口思路。
- 明确速度环不需要 16 kHz 角度刷新，但电流环 FOC 电角度需要尽量新。
- 快环中加入编码器快照和时间戳预测，降低 FOC 电角度滞后。

结果：

- 电角度预测补偿量实测较小，对主要问题改善有限。
- 速度环震荡的根因不能单独归因于测速算法，后续发现电流环死区过大才是空载规律震荡的重要原因。
- 速度环和位置环必须建立在稳定电流环基础上继续整定。

#### 3.10.4 低侧电流采样、三相重构和 ADC 触发点

现象：

- 早期相电流波形出现削顶，且削顶位置接近 ADC 中点 2048。
- 按 duty 判断有效窗口并重构后，波形改善，但动态重构相切换时 `id` 曾出现规律震荡。
- 关闭重构后电流环更差，说明低侧采样窗口确实需要重构或采样点约束。

检查和修改：

- 修改过 ADC 触发 CCR 计算，使采样点避开 PWM 边沿、死区和振铃区。
- 增加 VOFA 对 raw / 重构后电流 / 重构相 / ADC 触发 CCR 的观察。
- 尝试固定重构相，发现固定后 `id` 可明显变稳，但负载下会尖叫、卡顿，说明固定重构相只能定位问题，不能作为正常运行方案。
- 尝试过重构相滞回和最小保持周期。

结果：

- 动态重构相/采样点确实会影响低电流区 `id` 波动。
- 但最终空载规律震荡的主因不是重构切换本身，而是电流环死区过大。
- 后续仍需保留对采样窗口、重构相和 ADC CCR 的 VOFA 观测能力。

#### 3.10.5 新 4010 电机参数与相序/方向验证

现象：

- 更换新电机后，根据电机参数重新评估电流环参数。
- 新电机为 24N22P、极对数 11、相电阻约 8.6 欧、线绕参数 40、12-24V、最大瞬时电流约 2A。
- 校正时观察到电机从 0 到 2pi 方向和预期相反。

检查和修改：

- 更新了极对数等相关配置用于验证新电机。
- 讨论过电机 UVW 未标识时如何确认相序：先保证软件 PWM 相、ADC 采样相和实际驱动相一一对应，再通过小电流开环/闭环验证方向。
- 明确电机三相线本身可以互换，但软件中的 PWM 相序、ADC 相序、编码器方向和 FOC 电角度必须整体一致。

结果：

- 当前新电机能够进入稳定电流环状态。
- 相序和编码器方向后续仍应在速度环、位置环接入后继续低风险验证。

#### 3.10.6 电角度 offset 校正问题

现象：

- 不校正时，三相电流和 `i_alpha/i_beta` 在有有效电流时反而更接近正弦。
- 一旦进行电角度 offset 校正，`id` 曾出现规律震荡，波形变差。
- 这导致一度怀疑校正公式、编码器方向、d 轴吸附是否存在 180 度歧义。

检查和修改：

- 将两点校正暂时关闭，回到单点 d 轴吸附。
- 把 offset 计算公式抽成可切换形式：

```text
offset = wrap(ALIGN_ELEC + MECH_SIGN * mech_angle * pole_pairs)
```

- 用 `MOTOR_FOC_OFFSET_ALIGN_ELEC_RAD` 和 `MOTOR_FOC_OFFSET_MECH_SIGN` 验证吸附角定义和机械角符号。

结果：

- 校正链路仍需保留，因为上电初始机械角随机，不能依赖“刚好不校正能跑”。
- 但本轮最终确认，空载规律震荡的主要矛盾不是 offset 本身，而是电流环死区过大。
- 后续校正逻辑应继续使用单点吸附先验证，避免两点 ramp 过程引入额外变量。

#### 3.10.7 电流环死区过大导致空载规律震荡

现象：

- 空载时 `id` 规律震荡，电机有类似步进或吸附感。
- 有负载或手按电机时反而稳定。
- 单独看 `vq/vd` 有时并不剧烈，但 `id` 会呈周期性包络。

最终原因：

- 电流环死区设置过大。
- 空载小电流时，真实反馈和误差都很小，过大死区会让控制器长时间不动作。
- 误差积累到越过死区后，控制量突然介入，形成周期性震荡。

处理结果：

- 调小电流环死区后，电机空载和负载稳定性明显改善。
- 当前电流环基本稳定，这是本轮联调最重要的收敛点。
- 后续整定速度环和位置环前，必须记录并保持当前有效死区，不要再次把死区放大。

#### 3.10.8 速度环和位置环当前结论

现象：

- 速度环曾出现啸叫、卡顿、`iq_ref` 周期波动。
- 位置环已经能初步工作，但受速度环和电流环稳定性影响明显。

处理结论：

- 速度环输出只应作为 `iq_ref`，位置环输出只应作为 `speed_ref`。
- 外环需要在电流环稳定后重新整定，不能在电流环死区过大时判断外环参数好坏。
- 当前应以“稳定电流环 -> 低增益速度环 -> 位置环”的顺序继续。

当前状态：

- 位置环基础链路已基本完成。
- 当前重点应转为在稳定电流环基础上重新整定速度环，降低啸叫和规律速度波动。

### 3.11 2026-06-03 速度环、位置锁定和三线机构控制思路补充

本节记录在电流环基本稳定后，继续调试速度环、位置环和软体机器人三线控制方式时形成的结论。记录重点仍按“三要素”整理：现象、原因判断、修改/处理结果，并额外列出注意事项。

#### 3.11.1 KEY2 速度环阶跃测试序列

现象：

- 需要单独观察速度环从一个目标速度切换到另一个目标速度时的跟踪速度、超调和 `iq_ref` 输出变化。
- 原 KEY2 逻辑第一次按进入速度环目标 `20 rad/s`，第二次按直接停止，不方便观察 `20 -> 35 -> 20` 这种速度阶跃过程。

原因判断：

- 速度环问题不能只看单一目标速度。
- 需要在不改控制算法的前提下，用按键生成可重复的目标速度阶跃序列，方便 VOFA 对比目标速度、实际速度、速度误差、`iq_ref` 和速度 PID 各项输出。

修改/处理结果：

- 在 `main.c` 中增加 KEY2 速度测试步进状态。
- 当前 KEY2 循环为：

```text
第一次按：速度环目标 20 rad/s
第二次按：速度环目标 35 rad/s
第三次按：速度环目标 20 rad/s
第四次按：停止并关闭 PWM
再次按下：重新从 20 rad/s 开始
```

- 该修改只改变测试入口，不改变速度环、电流环和 FOC 算法。

注意事项：

- KEY2 当前仍是调试入口，不能作为最终业务状态机。
- 速度阶跃测试时应先低电流、短时间、低负载验证，避免参数不稳时长时间啸叫或过流。
- 若后续 KEY2 改为三电机选择/位置帧测试，应先记录当前测试序列，避免丢失可复现实验条件。

#### 3.11.2 速度环 P 项目标附近震荡

现象：

- 速度环只给较小 P 项时，实际速度仍会在目标速度附近来回震荡。
- 观察到速度 PID 中 I 项较稳定，而 P 项随速度误差正负切换来回跳动。
- P 项太小会导致速度跟踪慢，P 项稍大又会在目标附近因为小误差和速度噪声产生反向输出，造成 `iq_ref` 周期波动。

原因判断：

- 固定 `Kp` 同时承担“远离目标时快速跟踪”和“接近目标时平稳保持”两个任务，矛盾较大。
- 远离目标时需要较大 P 项提供快速加减速；接近目标时需要降低 P 项敏感度，避免速度误差小幅波动直接变成转矩指令。
- 速度环硬死区不能很好解决这个问题，因为通用 PID 死区会直接把误差置零，可能让目标附近控制变软。

修改/处理结果：

- 在 `Config.h` 中增加速度环 P 项误差相关缩放参数：

```text
SPEED_PID_KP_MIN_SCALE
SPEED_PID_KP_FULL_ERROR_RAD_S
```

- 在 `Motor_Core_UpdateSpeedPid()` 中根据速度误差临时缩放速度环 `kp`：

```text
误差 >= SPEED_PID_KP_FULL_ERROR_RAD_S：使用完整 Kp
误差 <  SPEED_PID_KP_FULL_ERROR_RAD_S：按线性比例降到最小 Kp 比例
```

- PID 计算前临时修改 `motor->control.speed_pid.param.kp`，计算后恢复原值，避免永久污染 PID 参数。

注意事项：

- 该方法不是改变速度环目标，而是改变 P 项在不同误差区间的敏感度。
- `SPEED_PID_KP_MIN_SCALE` 太小会导致目标附近锁定发软；太大则目标附近仍可能震荡。
- `SPEED_PID_KP_FULL_ERROR_RAD_S` 太小会过早使用完整 P，目标附近抖动可能恢复；太大则远离目标时也被削弱，跟踪变慢。
- 速度环死区当前仍要重点关注：如果 `SPEED_DEADBAND_RAD_S` 仍较大，通用 PID 会把小速度误差置零，但已有积分仍参与输出，可能导致目标附近漂移。

#### 3.11.3 速度环积分分离和泄放

现象：

- 速度环跟踪慢时，容易怀疑需要加大积分。
- 但加大积分后，速度阶跃、堵转释放或位置锁定附近可能出现积分残留，导致过冲或慢慢漂过目标。
- 大速度误差阶段如果积分持续累加，等速度接近目标时积分可能还在原方向推动。

原因判断：

- 速度环积分主要用于消除稳态误差、补偿负载和摩擦，不适合在大误差加速/刹车阶段快速堆积。
- 大误差阶段主要应由 P 项和电流限幅决定响应；积分应冻结或缓慢泄放。
- 小误差阶段仍需要积分，否则带负载位置保持会发软。

修改/处理结果：

- 在 `Config.h` 中增加：

```text
SPEED_PID_INTEGRAL_ENABLE_ERROR_RAD_S
SPEED_PID_INTEGRAL_LEAK_FACTOR
```

- 在 `Motor_Core_UpdateSpeedPid()` 中，当速度误差大于阈值时：

```text
速度积分 *= SPEED_PID_INTEGRAL_LEAK_FACTOR
本次 PID 临时关闭积分
PID 计算后恢复原积分使能配置
```

- 这样大误差阶段不会继续积累速度积分，小误差阶段仍允许正常积分。

注意事项：

- 不能简单把速度环积分永久关闭，否则位置锁定和负载保持能力会下降。
- 泄放系数越小，积分退得越快，但负载保持力也更容易被削弱。
- 阈值越小，积分只在非常接近目标时工作；阈值越大，积分更容易参与跟踪，但过冲风险更高。
- 速度积分的符号和位置误差方向必须结合观察，不能只看速度误差。

#### 3.11.4 位置环从“死区清零”改为“锁定区”

现象：

- 原位置环到达死区后会清位置 PID、清速度 PID，并把 `speed_ref`、`iq_ref` 清零。
- 这样到位后不是伺服锁死，而是接近“松手”。
- 带负载或外力推动时，只有误差跑出死区后才重新输出，表现为保持不硬、边缘晃动或不能可靠锁住。

原因判断：

- 对伺服位置控制而言，到位附近不应是“不控制区”，而应是“小范围保持区”。
- 位置死区把误差直接吃掉，会降低保持刚度。
- 直接清 `iq_ref` 或清速度环积分会导致带负载时突然泄力，后续用于拉索机构存在安全风险。

修改/处理结果：

- 在 `Config.h` 中增加位置锁定区参数：

```text
POS_LOCK_ENTER_RAD
POS_LOCK_EXIT_RAD
POS_LOCK_KP_DEFAULT
POS_LOCK_KD_DEFAULT
POS_LOCK_SPEED_LIM_RAD_S
```

- 在 `motor_core.c` 中增加 `s_position_lock_active[MOTOR_COUNT]`，用进入阈值和退出阈值形成滞回。
- 锁定区内不清 `speed_pid`、不清 `iq_ref`，而是用小范围位置刚度和速度阻尼输出速度目标：

```text
speed_ref = POS_LOCK_KP_DEFAULT * pos_error
          - POS_LOCK_KD_DEFAULT * actual_speed
```

- 锁定区外仍使用普通位置 P + 速度阻尼：

```text
speed_ref = POS_PID_KP_DEFAULT * pos_error
          - POS_VEL_DAMPING_GAIN_DEFAULT * actual_speed
```

注意事项：

- `POS_LOCK_ENTER_RAD` 和 `POS_LOCK_EXIT_RAD` 是锁定状态阈值，不再表示“控制死区”。
- 锁定区内仍然保留位置误差，不能把误差置零。
- 锁定区速度限幅过小会导致被推开后拉回慢；过大则到位附近可能动作过猛。
- 模式切换或停止时需要清 `s_position_lock_active`，避免下次启动继承旧锁定状态。

#### 3.11.5 位置锁定区速度积分漂移问题

现象：

- 位置锁定后，角度可能逐渐积分变大并超过目标角度。
- 表现为一开始已经锁住，但随后保持电流或速度环积分慢慢把电机推过目标。
- 位置环本身当前没有积分，因此漂移主要来自速度环积分。

原因判断：

- 锁定区内位置环只输出较小 `speed_ref`，速度环为了消除微小速度误差会继续积分。
- 当位置误差已经接近 0 时，速度积分如果仍在原方向，会继续输出 `iq_ref` 偏置。
- 若速度环死区较大，通用 PID 会把小速度误差置零，但已有积分仍参与输出，反而更难靠反向误差消掉积分。

修改/处理结果：

- 在 `Config.h` 中增加锁定区速度积分泄放参数：

```text
POS_LOCK_SPEED_I_REVERSE_LEAK_FACTOR
POS_LOCK_SPEED_I_CENTER_LEAK_RAD
POS_LOCK_SPEED_I_CENTER_LEAK_FACTOR
```

- 在位置锁定区内增加速度积分方向约束：

```text
如果 pos_error * speed_pid.integral < 0：
    说明速度积分正在把电机往目标外推，快速泄放
否则如果 abs(pos_error) 很小：
    对速度积分轻微泄放，避免长期堆住
```

- 该逻辑只在位置锁定区生效，不影响普通速度环模式。

注意事项：

- 该修改不是清空积分，而是有条件泄放，目的是保留负载保持力。
- 如果仍然漂过目标，可适当减小 `POS_LOCK_SPEED_I_REVERSE_LEAK_FACTOR` 或增大中心泄放范围。
- 如果带负载保持变软，可适当增大泄放系数或减小中心泄放范围。
- 后续仍建议把速度环硬死区减小到 0 或极小值，再观察锁定区积分是否更容易自然反向消除。

#### 3.11.6 速度环死区处理结论

现象：

- 速度环目标附近震荡时，直觉上会想增加速度死区。
- 但位置锁定区需要小速度误差也能产生保持力。
- 当前通用 PID 的死区实现是直接将 `abs(error) < deadband` 的误差置为 0。

原因判断：

- 对速度环而言，硬死区会让小误差不参与 P 和积分更新。
- 但是 PID 旧积分仍会参与输出，因此死区可能造成“误差不反向修正、积分仍在推”的问题。
- 当前已经增加了速度 P 项误差相关缩放、速度积分分离和锁定区积分泄放，因此不应再主要依赖硬死区抑制震荡。

修改/处理结果：

- 当前已明确建议：速度环死区应改为 0 或极小值。
- 但截至本节记录，代码中 `SPEED_DEADBAND_RAD_S` 是否最终改为 0 需要以当前 `Config.h` 为准，不能只凭记忆判断。

注意事项：

- 如果 `SPEED_DEADBAND_RAD_S` 仍为较大值，调位置锁定时必须把它作为重点风险项。
- 推荐后续测试顺序：

```text
先记录当前速度环死区
再尝试 0.05 rad/s
再尝试 0.0 rad/s
比较锁定区保持力、速度噪声和积分漂移
```

- 改死区前后必须同时观察 `speed_error`、速度 P 项、速度 I 项、`iq_ref` 和实际角度漂移。

#### 3.11.7 三电机同时闭环的计算负载风险

现象：

- 当前单电机 2 号链路已经能够较稳定驱动。
- 但三电机同时运行时，需要同时承担三路 16 kHz 电流环、三路速度环、三路位置环和 SPI 编码器采样。
- 单电机能跑通不代表三电机同时闭环一定可靠。

原因判断：

- 三电机 16 kHz 电流环意味着每秒约 48k 次电流测量、PID、FOC 和 CCR 更新。
- SPI3 若作为多编码器共享总线，三路编码器不能同时读，必须排队调度。
- 电流环电角度不能每次都等待 SPI 新数据，应使用最近角度缓存和速度预测。
- 当前很多优化主要围绕 motor2 / TIM20 / ADC1 / encoder3 做过，motor0 和 motor1 的快环链路仍需逐个验证。

修改/处理结果：

- 当前尚未把三电机同时闭环作为代码主线实现。
- 已形成测试策略：

```text
阶段1：三电机分别单独跑通
阶段2：三电机只开电流采样和编码器采样，不输出 PWM
阶段3：三电机低电流电流环，不开速度/位置环
阶段4：三电机低速速度环
阶段5：三电机位置环和上层帧调度
```

- 建议后续增加运行时负载观测：电流环执行耗时、SPI 一轮读取耗时、TIM7 是否丢周期、各电机 update_count 和 encoder error count。

注意事项：

- 不要因为单电机稳定就直接三电机高速位置闭环。
- 三电机编码器采样频率不应简单等于电流环频率。
- 推荐结构：

```text
电流环：PWM/ADC 同步，高频
编码器：SPI 轮询调度，中频
速度环：约 1 kHz 或更低
位置环：约 200-400 Hz
```

- 三电机同时运行时，VOFA 发送频率和通道数量必须降低，否则会干扰实时判断。

#### 3.11.8 多电机位置帧序列和路径问题

现象：

- 软体机构控制不是简单把三个电机直接移动到最终位置。
- 例如：

```text
frame1: M0 -> 3 rad, M1 -> -1 rad, M2 -> -2 rad
frame2: M0 -> 2 rad, M1 -> -2 rad, M2 -> 0 rad
```

和直接执行：

```text
M0 -> 2 rad, M1 -> -2 rad, M2 -> 0 rad
```

最终位置可能相同，但中间路径、姿态、受力和缠绕方式完全不同。

原因判断：

- 拉索软体机器人具有明显路径依赖和接触/摩擦/弹性变形影响。
- 上层不能只保留最新目标位置，否则会跳过中间帧，丢失预期运动过程。
- 需要区分底层单电机伺服闭环和上层多电机运动帧调度。

修改/处理结果：

- 当前形成方案：后续应增加轻量 `motion_app` 或等价上层调度模块。
- 上层保存帧队列，每一帧包含三电机目标位置或更高层形态目标。
- 当前帧完成后再进入下一帧，而不是收到新目标就直接覆盖当前运动。

注意事项：

- CAN/FDCAN 协议后续应按“运动帧”设计，而不是只按单电机目标设计。
- 每帧至少应考虑：

```text
frame_id / seq
三电机目标或形态目标
速度限制
保持时间
是否等待全部到位
是否允许中途覆盖
急停/清队列标志
```

- 对拉索机构而言，中间帧本身就是动作的一部分，不能被优化掉。

#### 3.11.9 三线机构的 alpha/beta/common 和等效螺旋参数

现象：

- 用户提出三根拉线是否像三相电流一样有关系，是否可以通过两根线重构第三根线。
- 进一步讨论到：中间弹性层放松线缆后整体更直，表现为等效对数螺旋参数变大；三线拉直趋近于直线；单根线强拉趋近设计时的卷曲螺旋。

原因判断：

- 如果三根线在截面上约 120 度均匀分布，可以把三根线长度变化分解为：

```text
alpha：二维弯曲分量之一
beta：二维弯曲分量之二
common：三线共同收放/预紧分量
```

- 这和 FOC 中三相到 alpha/beta 的思想类似，但物理含义不同。
- 三线理论上可分解为两个差动弯曲自由度加一个共同预紧自由度；不建议简单省掉第三根线，因为第三根线对预紧、防松弛、刚度和抓握力很重要。

修改/处理结果：

- 当前只是控制建模方案讨论，尚未写入代码。
- 推荐上层形态控制变量从直接三电机位置，逐步抽象为：

```text
bend_dir：卷曲方向
bend_amount：卷曲程度/等效曲率强度
common：三线共同预紧/刚度
```

- 三线目标可以用类似变换生成：

```text
alpha = bend_amount * cos(bend_dir)
beta  = bend_amount * sin(bend_dir)

l0 = common + alpha
l1 = common - 0.5 * alpha + 0.866 * beta
l2 = common - 0.5 * alpha - 0.866 * beta
```

- 对于论文中的对数螺旋参数，建议区分：

```text
b_design：打印结构的几何设计参数
B_eff：当前形态表现出来的等效螺旋参数
u = 1 / B_eff：更适合作为控制变量的卷曲强度
```

注意事项：

- `b_design` 不应被当成电机实时直接控制量，它主要由结构几何决定。
- `B_eff` 或 `u` 可以作为当前形态的等效描述，但需要通过视觉、传感或实验标定建立线长到形态的映射。
- 三线同拉/同放不只是“位置变化”，还会改变预紧、刚度、抗松弛和抓握力基线。
- 当前阶段最实用的下一步不是复杂逆运动学，而是先标定：

```text
电机角度 -> 线长变化
线长差动 -> bend_dir / bend_amount / B_eff
common -> 线张力 / 刚度 / 抓握力
```

## 4. 当前主要困难

当前项目已经进入真实硬件 FOC 联调阶段，主要困难集中在以下几类。

### 4.1 电流采样真实性

现象：

- 空载时电流看起来较正常。
- 堵转或负载时三相电流波形可能畸变。
- 某些情况下 `ia + ib + ic` 不接近 0。

可能原因：

- 低侧采样窗口不足。
- ADC 触发点靠近开关边沿、死区或振铃区。
- 采样电阻没有 Kelvin 连接，地噪声影响采样。
- duty 过大或过小导致某相不可测。

当前处理：

- 限制 duty 范围。
- 尝试固定中点采样和动态采样点。
- 引入三相电流重构思路。

仍需验证：

- 不同转速、不同负载下 raw 是否可信。
- 堵转时三相电流和是否合理。

### 4.2 电角度 offset 精度

现象：

- 开环可以转。
- 带一点负载或手动阻挡时，有时像一个极一个极吸附。
- iq/id 可能存在耦合。

可能原因：

- offset 校准不够准。
- 编码器方向或极对数使用错误。
- Park/反 Park 符号或相序不一致。
- 校准时转子没有真正稳定吸附。

当前处理：

- 回退到单点 d 轴吸附校准。
- 使用 VOFA 观察电角度、offset、id/iq。

仍需验证：

- 校准后给 iq 时，id 是否保持接近 0。
- 正反方向转动时，iq/id 是否一致。

### 4.3 快环计算负载

现象：

- 电流环放 ADC 回调后电机更稳。
- 但系统响应变卡，VOFA 和按键可能变慢。
- 分频后系统压力下降，但电机可能变抖。

当前处理：

- 减少快环通用函数调用。
- 直接写 TIM20 CCR。
- 缓存固定寄存器值。
- 减少不必要的编码器更新。

仍需验证：

- 单电机快环 CPU 占用。
- 三电机同时闭环是否可承受。
- 是否需要进一步拆分高频内环和低频外环。

### 4.4 DRV 和功率级参数

现象：

- 曾出现 VDS/OCP 报错。
- 某些相曾经单独报错。
- 电机负载下平滑性仍不理想。

当前处理：

- 修正 SPI 配置。
- 读回寄存器确认配置。
- 当前为 6x PWM。
- 目前 TIM20 MCU 死区约 400ns，DRV 内部死区约 100ns。

仍需验证：

- 死区是否过长。
- 栅极驱动电流是否合适。
- OCP/VDS 阈值最终配置。

## 5. 当前建议调试顺序

为了避免多个问题叠加，后续建议按下面顺序推进。

### 5.1 先确认单电机基础链路

检查项：

- 编码器角度连续。
- 编码器 valid 稳定。
- DRV 无故障。
- PWM CCR 正常变化。
- ADC raw 正常更新。

### 5.2 再确认 offset 和相序

检查项：

- 单点校准能稳定完成。
- 校准后电角度连续。
- 给定小 iq 时电机方向符合预期。
- `id` 不应明显被激发。

### 5.3 再确认电流采样

检查项：

- raw 不削顶。
- 三相电流和接近 0。
- 堵转时电流波形仍可信。
- 不同 duty 下采样不失真。

### 5.4 再调电流环

检查项：

- 从小 iq_ref 开始。
- 限制 vd/vq 输出。
- 限制积分。
- 观察 id/iq、vd/vq、三相电流。

### 5.5 最后调速度环和位置环

检查项：

- 速度环先低速小目标。
- 速度环输出只作为 iq_ref。
- 位置环输出只作为 speed_ref。
- 每一层都有限幅。

### 2026-05-17 前后：电流环基础链路与电流采样混乱

现象：

- 电流环开始运行后，`id/iq` 波形不稳定。
- 三相电流 raw 和重构后的电流值在 VOFA 中表现混乱。
- 电机运行时像步进电机一样抖动，单独给小电流也不够平滑。
- 一开始只在电流环启动后采样电流，导致上电静态下无法提前判断 ADC 是否正常。

原因判断：

- 电流采样链路和控制链路耦合太紧，导致问题定位困难。
- 低侧采样在不同 PWM duty 下存在窗口不足的问题。
- 仅靠两相电流重构第三相时，`ia + ib + ic` 始终被强制接近 0，不能再用三相和是否为 0 判断采样真实性。
- ADC 原始值、零漂补偿值、重构值和 Park 后的 `id/iq` 混在一起看，容易误判。

解决方法：

- 将电流采样改为上电后就能持续观察，而不是只在电流环模式下采样。
- 增加 VOFA 电流主题，分别观察 raw、补偿后相电流、重构信息、`id/iq`。
- 明确三相电流重构逻辑：窗口不足的一相用另外两相重构。
- 引入 ADC 自校准和电流零漂校准流程，区分 STM32 ADC 校准、DRV CAL 和真实采样链路残差修正。

当前结果：

- 上电后可以直接通过 VOFA 检查电流 raw 和相电流。
- 电流环基础链路可运行，后续问题主要集中到采样窗口、重构相选择和 PID 参数。

注意事项：

- 两相重构第三相后，不能再用 `ia + ib + ic = 0` 作为采样有效性的唯一判断。
- 应重点看 raw 是否削顶、是否贴近 2048、是否有相位相关尖峰。

---

### 2026-05-20 前后：低侧采样窗口、动态 ADC 触发与重构相问题

现象：

- 转动时电流波形出现明显削顶，曾观察到接近 2048 的异常平台。
- `VOFA_TOPIC_PHASE_CURRENT` 中三相或重构项出现尖峰。
- 重构相选择在高速或 duty 变化较快时从阶梯状变成尖峰状，导致 `id` 不稳定。
- 关闭重构后，电流环更容易飞掉，说明低侧采样窗口确实存在问题。

原因判断：

- ADC 采样点靠近 PWM 边沿、死区或振铃区时，低侧采样不可信。
- duty 最大的一相低侧导通窗口最短，容易成为需要重构的相。
- 重构相在边界附近频繁切换，会把采样误差周期性注入 `id/iq`。
- 空转时电流小，采样误差占比更高；堵转或加负载后电流变大，误差比例下降，因此看起来更稳定。

解决方法：

- 修改动态 ADC 触发 CCR，根据 duty 和重构相计算下一周期采样点。
- 增加 ADC 触发保护边界 `guard`，避开 PWM 边沿区域。
- 增加重构相滞回和最小保持周期，减少边界频繁切换。
- 增加 VOFA 诊断，观察重构相、ADC 触发 CCR、重构使能状态。

当前结果：

- 重构逻辑对电流环稳定性是必要的。
- 动态采样点和重构相选择仍需要结合实际硬件、转速和负载继续验证。

注意事项：

- 重构相出现尖峰不一定是逻辑错误，高速时 VOFA 显示可能因为采样频率不足而显得尖锐。
- 但如果 `id` 和重构相切换严格同步抖动，应优先检查 ADC 触发点和重构相切换策略。

---

### 2026-05-20 至 2026-05-31：电角度校准、id 震荡与电流环死区

现象：

- 电角度校准后，`id` 反而出现周期性震荡。
- 不校准时三相电流看起来更像正弦，但这不能作为最终控制方案。
- 空转时 `id` 抖动明显，按住电机或加负载后电流变稳定。
- `vd/vq` 看起来相对稳定，但 `id/iq` 仍然抖动。

原因判断：

- 初期怀疑电角度 offset 不准、编码器滞后、反电动势补偿不足。
- 尝试电角度预测、补偿增益和反电动势补偿后，效果不明显。
- 后续确认一个关键原因：电流环死区设置过大，导致小误差区域控制输出不连续，引发空载规律震荡。

解决方法：

- 修正 FOC 电角度校准逻辑。
- 增加电角度预测和调试通道，观察预测补偿量。
- 尝试反电动势补偿，但未作为最终主解法。
- 缩小电流环死区，使小电流误差附近仍能连续调节。

当前结果：

- 电流环空载稳定性明显改善。
- 重要结论：`id` 周期性震荡不能只盯电角度，电流环死区和采样误差同样可能是主因。

注意事项：

- 不校准时波形看似正常，不代表 FOC 角度正确。
- 有负载变稳定时，不能直接判断角度正确；也可能只是电流变大后采样误差比例下降。

---

### 2026-05-31 前后：4010 新电机参数适配

现象：

- 更换 4010 电机后，原参数不再完全适用。
- 电角度校准时实际方向与预期相反。
- 空转时 `id` 跳变仍明显，电流环参数需要重新估算。

电机参数记录：

```text
型号：JZ4010
极槽：24N22P
电压范围：12~24V
相电阻：约 8.6 ohm
扭矩常数：约 0.21 N*m/A
最大瞬间电流：2 A
相电感：调试中曾按约 4.76 mH 估算
```

原因判断：

- 新电机电阻、电感、极对数、转动惯量和原电机不同。
- 原电流环 PI 参数和限幅不能直接照搬。
- 反电动势补偿建模需要可靠的 `Ld/Lq/we/Kv`，当前参数不完整，补偿只能作为小增益试探。

解决方法：

- 修改新电机相关配置和方向参数。
- 重新估算电流环参数，并从保守值开始调试。
- 尝试反电动势补偿和补偿增益，但实际改善有限。
- 仍以电流采样质量、电角度校准和电流环死区为主要优化方向。

当前结果：

- 4010 电机单电流环已经能稳定运行。
- 后续负载下仍需重新整定电流环、速度环和位置环参数。

注意事项：

- 新电机参数不要只按理论值一次写死，应保留调试余量。
- 反电动势补偿不能替代基础电流环稳定性。

### 2026-05-31 至 2026-06-03：速度环震荡、速度估计与位置环锁定

现象：

- 速度环接入后，电机会出现周期性震荡和啸叫。
- 只给很小 P 项，速度反馈仍然在目标附近上下波动。
- `iq_ref` 呈规律性波浪，速度环跟踪慢但又容易震荡。
- 位置环到目标附近时，目标速度在死区边缘震荡，伺服锁定不够硬。
- 位置死区内直接清零会泄力，后续带负载存在风险。

原因判断：

- 单次角度差分速度噪声较大。
- 速度环 P 项在目标附近来回反向输出，是震荡的重要来源。
- I 项相对平稳，但积分过强会导致响应慢或堵转后恢复差。
- 位置环简单死区不适合伺服锁定，容易出现边缘抖动和锁不住。

解决方法：

- 将速度计算改为一段时间内累计角度差 / 累计真实 DWT 时间的平均速度。
- TIM7 负责低频速度外环，SPI 回调只更新角度缓存和样本累计。
- 增加 `iq_ref` 低通。
- 速度环加入积分分离、泄放和小误差 P 衰减。
- 位置环从“死区”思路改为“锁定区”，并加入阻尼和积分泄放。

当前结果：

- 单电机速度环震荡降低到可接受范围。
- 位置环基本完成单电机验证，但带负载锁定安全性仍需实测。

注意事项：

- 速度环和位置环不要直接在高频 ADC 回调中执行。
- 速度环输出只应改变 `iq_ref`，位置环输出只应改变 `speed_ref`。
- 位置环上负载前，不能用“到位清零”这种会突然泄力的策略。

### 2026-06-03 至 2026-06-14：三电机框架迁移前的快环风险

现象：

- 单电机 motor2 已经基本可控，但三电机同时运行存在实时负载风险。
- 原来很多逻辑固定在 TIM20 / ADC1 / encoder3。
- 如果三电机都跑 16kHz 电流环，再叠加速度环、位置环和 SPI 编码器读取，可能导致中断负载过重。

原因判断：

- 快环中不必要的 ID 映射、函数跳转和重复三角函数会放大 CPU 开销。
- 原设计中部分通用保护判断在高频路径重复执行，调试阶段可以逐步精简。
- 三路编码器共用 SPI3，总线必须串行调度。

解决方法：

- 在 `motor_t` 中绑定每台电机自己的 ADC、编码器、PWM CCR、ADC 触发 CCR。
- 将 motor2 专用快环扩展为 `Motor_Core_RunCurrentFastLoopFromAdc(motor_id, dt)`。
- 保留旧 motor2 入口作为兼容调试接口。
- FOC 快环中复用同一组 `sin/cos`，避免 Park 和 InvPark 重复计算三角函数。

当前结果：

- 三路电流快环的软件结构已经具备。
- 是否能三路同时稳定运行仍需上板验证。

注意事项：

- 三电机迁移不能简单复制 motor2 逻辑，应先绑定资源，再让快环读绑定字段。
- 快环优化必须保持 FOC 限幅、SVPWM 和 duty 写回逻辑不变。

### 2026-06-14 前后：MT6816 编码器 SPI 读取与硬件风险

现象：

- 静止时编码器基本正常，转动时 parity/frame/no_mag 错误明显增加。
- 曾出现角度从约 2000 跳到 10000 的异常，导致电机震动。
- 换编码器芯片后部分异常消失。
- 多个编码器接入同一 SPI3 MISO 后，即使只读取一路，也可能疯狂报帧校验错误。
- 不接 MISO 或不接 MOSI/SCK 时，MISO 电平表现异常，说明硬件总线状态需要重点检查。

原因判断：

- 曾怀疑 SPI 频率、CS 时序、DMA 被中断打断、高低字节非同一帧。
- MT6816 的 0x03/0x04 角度寄存器读取方式需要严格按手册确认。
- 多编码器 MISO 并接要求未选中器件真正高阻，否则会互相拉扯。
- 线太长、上拉不足、CS 未可靠释放都可能导致校验错误。

解决方法：

- 对比 3 字节 burst read、4 字节读法、两次分开读 0x03/0x04。
- 采用 MT6816 burst read：`0x83 0x00 0x00`，解析 `rx[1]` 和 `rx[2]`。
- 保留分开读模式开关，便于后续回退。
- 优化 CS 建立/保持时间。
- SPI3 多次尝试不同分频，当前更关注总线硬件和调度。

当前结果：

- 单编码器读取可以稳定。
- 三编码器共总线仍需结合硬件高阻、线长和片选电平继续验证。

注意事项：

- 校验错误不一定是软件解析错误，也可能是 MISO 硬件总线冲突。
- 多编码器并接时，必须确认未选中器件 MISO 是否高阻。

### 2026-06-21：三路编码器 Pending 调度

现象：

- 原来三路编码器由 ADC1 统一触发 `SPI_Encoder_Start_Update_All_DMA()`。
- 三电机迁移后，每个电机的 ADC 回调都应该请求自己的编码器刷新。
- 但 SPI3 是共享总线，三个 ADC 回调不能同时启动 SPI DMA。
- DMA 完成后如果连续拉起下一路，会导致 SPI DMA 中断链过重，并且编码器刷新频率不再受控。

原因判断：

- 编码器请求源应该拆到 ADC4/ADC3/ADC1，但 SPI3 启动必须集中串行。
- pending 适合表示“该路需要刷新一次最新角度”，不适合做无限队列。
- 实际频率仍应由 ADC 分频控制，而不是 SPI 总线最大吞吐控制。

解决方法：

- 新增 `SPI_Encoder_Request_Update_DMA()`：只置 pending，不启动 SPI。
- 新增 `SPI_Encoder_ServicePendingOnce()`：SPI 空闲时最多启动一路 pending。
- ADC4/ADC3/ADC1 分别每 2 次请求 encoder1/encoder2/encoder3，目标约 8kHz。
- SPI DMA 完成回调只释放 CS、解析帧、更新缓存、清 busy，不自动连续启动下一路。
- 保留旧 `Start_Update_All_DMA()` 和 `Start_Update_One_DMA()` 调试接口。

当前结果：

- 三路编码器刷新结构已经从“ADC1 统一触发三路”改为“三路 ADC 请求 + SPI3 串行服务”。
- `git diff --check` 已通过。

注意事项：

- 如果 pending overwrite 或 missed 计数持续增长，说明 SPI 读取频率过高或总线异常。
- 后续需要把 pending/missed/valid 加到 VOFA 诊断中。

### 2026-06-22 至 2026-06-28：三路高速电流环迁移与实时负载评估

现象：

- 之前主要围绕电机3，即代码中的 `motor2`，单独优化电流快环，其余两台电机仍有旧入口或不完整迁移。
- 三台电机逐步同时开启时，单台运行正常，增加到两台或三台后出现程序卡死或控制停止。
- DWT 观测到单台完整电流快环约为 23us，但三路在原高频配置下没有足够的中断和主循环余量。
- 将 PWM 和电流环目标频率尝试提高到 12kHz 时仍存在时序和编译配置风险；更高频率下三路同时运行不稳定。

原因判断：

- 三路 ADC 回调、三路电流环、共享 SPI3 编码器 DMA、TIM7 外环和 VOFA 调试叠加后，最坏执行时间远高于单路测量值。
- 三台电机虽然拥有独立 PWM 和 ADC，但 CPU、SPI3、DMA 中断和部分数学运算仍然共享。
- 原代码中存在重复三角函数、重复电流处理、通用 ID 查询和高频路径中的冗余有效性判断。
- 三路控制不能共用一个 DWT `last_cycles`，否则其中一路更新会污染另外两路的实际 `dt`。

解决方法：

- 将三路电机分别绑定到各自 ADC、PWM、编码器和 ADC 触发资源。
- ADC4、ADC3、ADC1 分别驱动电机1、电机2、电机3的电流快环。
- 每台电机使用独立 DWT 时间戳，`dt` 表示该电机两次实际执行电流环之间的真实时间。
- Park 和 InvPark 复用同一次计算得到的 `sin/cos`，去除重复角度计算。
- 减少快环中的 ID 查询、重复绑定检查和无意义的通用保护判断。
- 增加 DWT 快环耗时观测，分别测量单路和多路运行时间。
- 最终将三路 PWM 和电流环频率统一为 10kHz，以换取稳定的实时余量。

当前结果：

- 三台电机均具备独立的 ADC 同步电流快环入口。
- 单路完整快环实测约 23us，10kHz 配置下的单路周期预算为 100us。
- 16kHz/12kHz 三路同时运行存在明显风险，10kHz 是当前实机使用的稳定配置。
- 当前 `Config.h` 中 `PWM_FREQ` 和 `MOTOR_CURRENT_LOOP_FREQ_HZ` 均按 10kHz 语义运行。

注意事项：

- 23us 是单路观测值，不能直接认为三路总耗时就是严格的 69us；中断抢占、SPI等待和缓存行为会增加最坏耗时。
- 修改 PWM 频率后，必须同步检查 TIM1/TIM8/TIM20、ADC触发点、电流环 `dt` 和速度/位置环分频。
- PID连续时间参数原则上不应只因采样频率变化而机械倍乘，但离散积分、滤波系数和限幅仍要重新确认。

### 2026-06-28 至 2026-06-29：三电机校正、电角度微调与方向统一

现象：

- 不校正时部分电机能够转动，执行校正后反而吸附或无法继续控制。
- 三台电机的机械转向、编码器方向、速度反馈方向和电角度微调曾相互叠加，导致“改一个方向后另一层又反掉”。
- 校正流程最初只完整服务单台电机，扩展为三台后曾出现状态未释放、校正完成后 PWM 中性输出仍保持等问题。
- 部分电机需要在校正结果中并入 90度电角度微调，另一些电机使用 0度时更正常。

原因判断：

- 机械反馈符号错误会把速度环或位置环变成正反馈。
- FOC电角度微调错误会造成吸附、发热、力矩偏小或类似步进电机的卡顿，不能用速度/位置反馈符号代替。
- 校正结束后如果没有正确停止 PWM、清理校正状态并恢复控制入口，会出现“校正后按键不能转”。
- 将方向修正分散在编码器、速度反馈、位置误差、CAN命令和最终目标多个位置，容易重复取反。

解决方法：

- 三台电机按顺序执行电角度校正，并在上电初始化后自动连续校正两轮。
- 每台电机单独保存校正得到的电角度 offset，禁止复用最后一台电机的结果。
- 电角度微调只在校正结果写入时一次性并入，不在每次 FOC 快环中重复计算。
- 将机械闭环反馈符号和 FOC 电角度微调分开管理。
- 尽量把命令方向修正集中到单一出口，减少 CAN、按键和映射层重复取反。
- 使用 KEY2 单电机测试宏，在电流环、速度环和位置环之间逐级验证。

当前结果：

- 三台电机能够分别完成校正，并具备各自独立的 offset。
- 上电自动校正轮数当前为 `MAIN_AUTO_FOC_CALIB_ROUNDS = 2U`。
- 三电机方向和电角度参数后来进一步迁移到板级配置文件中，不再假设所有驱动板完全一致。
- 2026-06-29 保存了 `Save three motor position control baseline`，表示三台电机位置控制主链路已经建立。

注意事项：

### 2026-06-28 至 2026-06-29：速度环与位置环迁移到三台电机

现象：

- 单台速度环调通后，另外两台电机仍可能使用旧的编码器、旧的反馈符号或共享外环状态。
- 大位置误差时，位置环会突然给出较大目标速度，切回近距离控制时又会发生速度突变和震荡。
- 到达锁定区边缘时，斜坡策略切换导致目标速度跳变。
- 速度环大误差完全禁止积分时，带载情况下可能长期卡在 P 项饱和区；完全不泄放又会造成超调。

原因判断：

- 位置环、速度环和电流环的状态必须按电机独立保存。
- 远距离运动适合限速巡航，接近目标后才适合由位置环连续减速和锁定。
- 大误差积分分离不能简单做成“积分开/关”，否则负载下可能没有足够稳态力矩。
- 锁定区与普通区域采用完全不同的速度命令处理，会在边界产生不连续。

解决方法：

- TIM7外环从 selected motor 逐步迁移为按活动 mask 更新三台电机。
- 每台电机单独保存速度计算累计量、速度PID、位置PID、斜坡状态和目标位置。
- 远距离位置误差采用巡航速度，接近目标后切回位置环，并设置进入/退出滞回。
- 非锁定区使用目标速度斜坡；锁定区仍保持闭环，不再简单清空输出泄力。
- 速度环改为大误差积分降额、小误差正常积分，并保留受限的反向泄放。

### 2026-07-02 至 2026-07-06：H7 手势识别与三拉索映射控制

现象：

- H7需要把VL53阵列和手势推理结果转换为三根拉索的目标位置。
- 仅使用三个电机目标角度难以表达弯曲方向、弯曲程度和整体预紧/刚度。
- 手在圆心附近轻微移动时，直接使用 `atan2` 会造成方向角快速跳变。
- 手突然离开检测区域时，不能让电机继续沿最后速度运动。

原因判断：

- 三根拉索在截面上相隔120度，控制量应拆成差动分量和共同分量。
- `x/y` 适合只决定弯曲方向，抓握程度适合决定弯曲幅度，距离适合决定共同预紧或刚度。
- 中心区域的方向向量模长太小，角度本身没有可靠意义。
- 电机机械正方向与“放绳/收绳”物理方向必须在最终映射出口统一。

解决方法：

- 将三根线视为相隔120度的三个轴，使用方向投影生成三路差动量。
- `x/y` 经过中心死区和限幅后只决定单位方向，不直接决定弯曲幅度。
- `bend` 决定差动量幅值，`stiff` 决定三路共同收放量。
- 无手检测时保持当前目标，不继续生成新动作。
- 中心区域停留配合快速抓握识别虚拟按键；单次抓握窗口约1s，双击等待窗口后续缩短到约1.5s方向。
- 以约320mm为距离分区，组合形成不同选择/开关语义。
- 增大最大弯曲差动行程，曾将 `bend=100` 对应的最大差动目标提高到约4500控制单位。
- 电机方向差异尽量只在最终目标出口做一次修正。

当前结果：

- H7已经具备从手势/位置/距离到三电机目标的映射框架。
- 形成了 `x/y + bend + stiff` 四个上层控制量，并通过CAN FD发送三电机同步目标。
- 映射范围、每块触手的机械方向和最大安全行程仍需通过实物逐板标定。

注意事项：

- 三路差动量理论上应保持零和或固定共同量，整体同拉同放必须单独由 `stiff` 控制。
- 方向修正不能同时存在于H7映射、CAN命令和G4闭环反馈多个层级。
- 映射调试必须先用小幅度目标确认三根线的收放方向，再逐步增大 `bend` 和 `stiff`。

原因判断：

- 仅停止定时器PWM并不一定保证功率级六个MOS立即进入高阻态。
- 高低侧输出脚、定时器空闲状态、DRV输入保持和CH4 ADC触发通道可能让桥臂处在非预期状态。
- 逐个停止三台PWM的执行时间不是主要矛盾；真正需要的是在停机语义上明确让DRV进入COAST。

解决方法：

- 在DRV8323 Driver Control寄存器中定义 `DRV8323_DRIVER_COAST = (1U << 2)`。
- `Motor_Core_StopPwmOutput()` 先置对应DRV的COAST位，再停止该电机PWM，使六个MOS进入高阻态。
- `Motor_Core_StartPwmOutput()` 先准备并启动PWM，再清除对应DRV的COAST位。
- 如果清除COAST失败，立即重新停止PWM，避免功率级输入状态不确定。

当前结果：

- COAST停机逻辑已经写入 `drv_drive.h` 和 `motor_core.c`。
- `git diff --check` 已通过。
- 尚未完成Keil全量编译和三块实机逐路验证，因此当前状态为“代码已修改，待实机确认”。

注意事项：

- COAST用于正常停机时释放电机，不代替过流、过温和紧急停机保护。
- 带负载触手是否允许自由滑行需要上层安全策略决定；某些工况可能需要制动或保持力矩，而不是COAST。
- 启动和停止均需要确认SPI写DRV寄存器成功，不能默默忽略失败状态。

### 12.1 2026-07-19 至 2026-07-31：多触手运行稳定性与控制链路收尾

现象：

- 单触手静止时 CAN 状态稳定，但运动后曾出现状态延迟、上位机显示掉线和自动停止；停止后节点又恢复在线。
- 四触手控制中，触手 4 的三路线缆方向一度不符合中心对称关系，出现三根线同时放松的情况。
- 上位机在未启动时切换模式或锁定参数后，界面显示的模式与 H7 实际运行模式可能不一致。
- W25Q64 频繁保存 ACTUAL 会占用主循环时间；只按固定周期保存又可能在停止后遗漏最后位置。

原因判断：

- G4 状态上报曾依赖 HAL SysTick；高频电机任务运行后，软件节拍和主循环负载变化会拉长状态帧间隔。
- H7 启动前的严格 READY 条件曾被错误复用于运行过程，把短暂状态延迟直接当作危险断连。
- 四触手安装方向、三电机收放线方向和协同关系变换分散在多个位置，触手 4 的方向修正不完整。
- 固定周期无条件写 Flash 会增加阻塞和擦写次数，且不能保证运动停止瞬间的最终位置一定入队。

处理方法：

- G4 状态上报改为固定硬件定时节拍分频，周期保持 50 ms，不再用 HAL SysTick 作为状态发送依据。
- H7 将“启动 READY”和“运行健康”分开：启动前严格检查在线、状态新鲜、无 FAULT 和恢复有效；运行中短暂波动仅告警，FAULT 与急停立即停止。
- 统一四触手工作模式、活动 mask 和方向表，触手安装差异只在固定映射层处理，不在 CAN、上位机和 G4 多处重复取反。
- W25 保存改为变化阈值触发和任务队列处理；运动停止后强制补记一次最终 ACTUAL，HOME 与 ACTUAL 保持同一快照语义。
- 上位机启动顺序固定为“下发模式 -> 查询并确认状态 -> MCTRL 1”，运行中不再用界面草稿代替 H7 实际状态。

当前结果：

- G4 改用固定定时节拍后，运动过程中的 CAN 卡顿明显下降；50 ms 状态周期满足当前监测需要。
- 单触手、双触手和四触手控制链路进入可演示状态，短暂 CAN 波动不再立即终止控制。
- 四触手方向仍需要逐触手使用小幅度命令做实物标定，不能仅依据软件符号推断最终收放线方向。

注意事项：

- 该阶段大量工作来自连续联调记录，没有为每次阈值调整单独提交 Git，因此日期采用范围表述。
- READY 放宽只针对短暂通信波动，不能放宽 FAULT、急停和实际位置失控保护。

### 12.2 2026-07-28 至 2026-08-06：单触手 ACT 方案与数据接口确定

目标：

- 使用触手 3 完成单触手示教学习演示。
- 通过 VL53L8CH 观察瓶子与触手状态，学习从初始位置到包裹瓶子的连续三电机轨迹。
- 保留每约 100 ms 重新感知和推理的能力，而不是只执行一次固定轨迹。

关键设计：

- 每个模型输入窗口使用连续 12 帧观测。
- 每帧 ToF 数据最终采用 18 个通道、8×8 区域，共 1152 个值；12 帧展平后为 13824 个值。
- 三电机 ACTUAL 作为独立输入，形状为 12×3，用于反映当前真实机械状态。
- 监督标签使用当前观测窗口之后的未来 10 帧三电机实际位置，形状为 10×3；不把当前帧命令错误地当作未来标签。
- 数据单位统一为 `q`，即 `1 q = 0.01 rad`，训练与 H7/G4 控制接口保持一致。

数据流：

```text
VL53L8CH 新帧 + 三电机 ACTUAL
-> H7 按同一采样时刻组帧
-> USART1 二进制采样帧
-> ACT 专用上位机校验并缓存
-> 一次完整抓取形成一个 Episode
-> 用户确认后保存，失败样本删除
-> 滑窗生成 12 帧输入和未来 10 帧标签
```

接口取舍：

- USART7 继续负责普通运动控制和命令反馈，USART1 专门发送 ACT 采样数据，避免控制文本与大数据帧互相干扰。
- 单个 Episode 先保存在 PC 内存中，结束后由用户选择保存或删除，不在每帧到达时生成大量零散文件。
- 二进制协议使用帧头、长度、样本序号和 CRC；PC 端遇到坏帧后重新搜索帧头，避免一次错位造成后续持续 CRC 错误。
- 采样帧只复制当前稳定缓冲区，H7 使用双缓冲隔离传感器更新和串口发送，避免发送过程中数据被覆盖。

当前结果：

- ACT 模型输入、标签、采样串口和 Episode 保存语义已经固定。
- 该阶段确定“模型输入不包含未来命令”，未来三电机位置只在训练阶段作为监督标签使用。

### 12.3 2026-08-06 至 2026-08-08：ACT 采集上位机与串口稳定性

现象：

- 初期采样只有 6 至 9 Hz，时间显示变化不均匀，CRC 错误有时会连续出现。
- 通过 USB 扩展坞连接时错误率明显上升；更换数据线或直接连接电脑后可达到约 11 Hz。
- 串口长帧发生一次错位后，旧解析器可能从错误位置继续解释，造成后续连续 CRC 失败。
- ToF 读取量、H7 成功组帧量和 PC 接收量不是同一个统计量，直接比较容易误判瓶颈。

处理方法：

- USART1 采样波特率最终使用 921600，避免过高速配置增加 USB 转串口和线缆误码。
- PC 解析器在 CRC 或长度异常后逐字节搜索下一处有效 magic，不把坏包之后的所有数据整体丢弃。
- 分别统计 ToF 新帧数、H7 打包数、UART 发送数、PC 收包数和 CRC 错误数，区分传感器帧率、发送拥塞与链路误码。
- VL53L8CH 工作频率与实际推理周期最终收敛到约 10 Hz；原始采集可在约 11 Hz 下记录，再在清洗阶段统一重采样。
- 上位机增加 Episode 开始、停止、保存、删除、帧数、时长、CRC 和序号跳变显示。

当前结果：

- 2026-08-08 保存 Git 节点 `4bfa32a Save ACT acquisition firmware baseline`。
- 采样链路能够持续保存完整 Episode，串口直连电脑时稳定性明显优于扩展坞。
- `ACT_PC_BUILD_WORK` 中形成采集上位机、协议、Episode 缓冲、测试和设计文档。

注意事项：

- CRC 错误只能说明传输帧不可信，不能直接说明 VL53 数据或模型错误。
- PC 显示帧率按成功通过协议校验的完整帧计算，不等于 I2C 测距启动次数。

### 12.6 2026-08-11 至 2026-08-12：ACT 实机控制、动作块融合与震荡诊断

现象：

- 第一版模型有时直接跳向动作末端，未完整复现示教中的抬升、横向避线和下降包裹阶段。
- 每约 100 ms 重新推理时，相邻预测块对同一未来时刻的目标并不完全一致，电机可能在两个目标之间来回反转。
- 只取未来第 3 帧能够加快动作，但容易跳过中间阶段；只取最新第 1 帧又容易受预测噪声影响。
- 换场景或改变瓶子位置后震荡加重，说明训练分布和场景泛化仍有限。

处理方法：

- 每个动作块保存对应 `frame_seq`，根据当前序号计算 `frame_delta`，只融合对齐到同一物理时刻的预测。
- 多个旧动作块按时间衰减加权；普通丢一帧不清空历史，长时间间隔或序号异常才重置。
- 模型输出先经过时序融合，再按当前 ACTUAL 限制最大领先量，并按上一次已发送目标限制单周期步长。
- 增加 `ACTOSC?` 诊断，同时记录模型目标、已发送目标和实际位置的范围、回退量和反向次数，避免仅凭肉眼修改阈值。
- ACT 默认关闭，仅控制训练对应的触手 3，活动 mask 固定为 `0x04`；故障停止后不自动恢复运行。

当前结果：

- 时序融合降低了相邻目标跳变，能够继续保持每约 100 ms 根据最新环境重新推理。
- 模型预测、限幅后目标和物理 ACTUAL 的震荡来源可以分开观察。
- 该修改只能缓解滚动预测不一致，不能替代数据分布和模型训练；跨场景阶段漂移仍属于模型问题。

安全边界：

- `FAULT`、急停和已确认的控制超时仍需停止；安全停止原因通过 `MSTOP` 一次性返回。
- 震荡检测不能因单次 mask 消失立即清零长期计时，也不能因另一台电机稳定就降低正在震荡电机的融合等级；相关阈值需要通过 ACTOSC 连续数据验证。

## 13. 截至 2026-09-29 的最终工程状态

### 13.1 已完成并形成文件证据

1. STM32G474 三电机 FOC、电流/速度/位置分层闭环及板级 profile。
2. STM32H743 的 VL53L8CH 感知、手势 CNN、ACT Delta-TCN、W25Q64、CAN/FDCAN 和双串口链路。
3. 单触手、双触手和四触手的上层控制与状态管理框架。
4. ACT 二进制采样协议、专用上位机、Episode 缓存与确认保存流程。
5. 221 条原始 Episode 的清洗、划分和 214 条有效数据集。
6. Transformer 教师/基线评估、TCN/Delta-TCN 训练、ONNX 导出和 Cube.AI 代码生成。
7. H7 双模型共存、ACT 约 101 至 102 ms 在线推理和串口诊断。
8. 动作块时序对齐融合、目标步长/领先限制及 model/sent/actual 三类震荡观测。
9. iCAN 开发日志、实验图表、软著源码文档和用户操作手册。
10. G4/H7/上位机/训练/模型的 GitHub 发布仓库。

### 13.2 已实现但仍需要继续量化

- ACT 在固定背景和受控瓶子位置下的重复抓取成功率。
- 不同瓶子位置、姿态、光照和背景变化下的跨场景泛化能力。
- 动作阶段完整性、平均完成时间、三电机目标跳变量和实际反向次数。
- 四触手同时运行时长、CAN 丢帧率、FAULT/STOP 响应时间和温升。
- W25Q64 写满回绕、多次断电和重新烧录后的恢复可靠性。
- 各 G4 板电机方向、电角度 offset、电流采样和 COAST 停机的一致性。

### 13.3 当前最高风险

- ACT 模型可能在训练分布外出现阶段跳跃、局部卡住或目标震荡。
- 一次推理约 101 至 102 ms，感知、推理和控制实际属于约 10 Hz 策略层，不能承担 G4 的高频实时闭环职责。
- 多触手安全依赖 G4 STOP 锁存、编码器新鲜度、H7 故障仲裁和上位机状态确认共同成立。
- 发布仓库不包含训练原始数据和全部历史快照，复现实验仍需保留本地数据归档。

### 13.4 后续建议顺序

1. 在独立目录重新克隆 GitHub 仓库，验证 H7/G4 工程入口和 Python 训练依赖。
2. 固定瓶子、背景、初始姿态和停止条件，完成不少于一组可统计的重复抓取实验。
3. 记录成功/失败、完成时间、最大温升、CAN 超时、目标反向次数和实际轨迹。
4. 根据失败类型决定补数据、重训模型或修改执行限制，不继续无依据叠加状态机。
5. 实机验证通过后再发布 HEX、上位机 EXE 和模型 Release，并在 README 标明硬件版本与烧录顺序。
